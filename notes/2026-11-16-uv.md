# uv：Python 的包与环境管理器

## 一句话理解

`uv` = pip（装包）+ venv（建虚拟环境）+ 锁文件（记录精确版本），一个命令全干完，速度是 pip 的几十倍。

## 三个文件各是什么

| 东西 | 类比 | 作用 | 要不要提交到 Git |
|---|---|---|---|
| `.venv/` | 你电脑上的工具柜 | 实际存放包的地方 | 不提交（已在 .gitignore） |
| `pyproject.toml` | 购物清单 | 你「想要」哪些包，写版本范围 | 提交 |
| `uv.lock` | 购物小票 | 实际「装上了」哪个精确版本 | 提交 |

为什么锁文件也要提交：别人（或半年后的你）clone 下来跑 `uv sync`，装到的版本和你一模一样，不会出现「我这儿能跑你那儿报错」。

## 和 requirements.txt 的区别

- `requirements.txt`：只有一份清单，靠手写 `pip freeze` 导出，容易漂移。
- `pyproject.toml` + `uv.lock`：清单 + 精确锁定，还能写项目名、Python 版本要求、脚本入口。现在新项目都用这套。

## 常用命令（在项目根目录执行）

```bash
uv init --bare              # 只生成 pyproject.toml，不动其他文件
uv venv --python D:/python/python.exe   # 建 .venv，指定用哪个 Python
uv add requests             # 装包：同时改 pyproject.toml、更新 uv.lock、装进 .venv
uv remove requests          # 卸包，同样三处一起改
uv sync                     # 按 uv.lock 把 .venv 装成应有的样子（clone 后第一步）
uv run python xxx.py        # 在虚拟环境里跑脚本，不用手动 activate
uv run pytest               # 同理，跑测试
```

## 最关键的一点

**不用手动 `activate`。** 传统做法是 `.venv\Scripts\activate` 再 `python xxx.py`，忘了激活就会用错环境。uv 的做法是 `uv run python xxx.py`，它每次自己找 `.venv`，永远不会搞错。

什么时候还是要 activate：想在 VS Code 里点右上角「运行」按钮，或者用交互式 `python` 时。VS Code 选解释器时选 `.venv\Scripts\python.exe` 即可。

## 记住的验收标准（12/6 闸门 ③）

空文件夹 → 5 分钟内：`uv init --bare` → `uv add 某包` → `git add/commit/push`。
