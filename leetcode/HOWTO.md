# 每天一道 LeetCode · 操作流程

总时长 30 分钟。**25 分钟硬上限**，到点没做出来就看题解，不纠结。

## 一、30 分钟怎么分

| 阶段 | 时长 | 做什么 | 不许做什么 |
| --- | --- | --- | --- |
| ① 开题 | 2 min | 按题单顺序拿下一题；新建文件；写文件头注释 | 不许直接看题解 |
| ② 独立做 | 18 min | 在注释里先用人话写思路，再写代码 | 不许看提示、不许搜 |
| ③ 看题解 | 5 min | 只看「方法一」的文字说明，不滑到代码 | 不许抄代码 |
| ④ 重写 | 4 min | 关掉题解，从空函数重新写一遍，跑通示例 | 不许留着题解窗口 |
| ⑤ 记录 | 1 min | 更新 `INDEX.md` 一行 + 补齐文件头三行 | 不许跳过 |

@②卡住时必做：在注释里写下「我卡在哪一步」。这句话是这道题唯一的产出。

## 二、文件怎么建

命名：`题号-英文名.py`，题号补足四位。

```
leetcode/0026-remove-duplicates.py
leetcode/0027-remove-element.py
```

文件模板（直接复制）：

```python

if __name__ == "__main__":
    print(solution([1, 1, 2]))      # 期望 2
```

**必须有 `if __name__ == "__main__":` 和至少两个测试用例**，包括一个边界情况（空数组 / 单个元素 / 全相同）。写完跑一遍再提交：

```bash
python leetcode/0026-remove-duplicates.py
```

## 三、INDEX.md 加一行

```markdown
| 11/08 | 26 | 删除有序数组中的重复项 | [代码](0026-remove-duplicates.py) | 是 | 22m | 双指针 / 原地修改 |
```

「独立做出」只填 `是` 或 `否`。填 `否` 不可耻，它是周日复盘时唯一有用的信息。

## 四、提交

```bash
git add leetcode/
git commit -m "feat(leetcode): 26 删除有序数组中的重复项"
git push
```

**每天一条提交**，不要攒一周。提交信息固定格式：`feat(leetcode): 题号 题目名`。

## 五、周日复盘（15 分钟）

1. 打开 `INDEX.md`，只看「独立做出 = 否」的行
2. 重做一遍：做对了把「否」改成 `✅`；还是不会标 `⚠️`
3. 把 `⚠️` 挑一道，下周找个空档再看一次题解

做对了的题不用重做——那部分已经属于你。

## 六、题目顺序（按专题，不随机）

| 阶段 | 题号 | 主题 |
| --- | --- | --- |
| 第 0–1 周 | 1, 26, 27, 88, 283, 217, 344 | 数组 / 双指针 / 哈希 |
| 第 2 周 | 242, 20, 53, 121, 70, 136 | 字符串 / 栈 / 递推 |
| 第 3–4 周 | 206, 21, 141, 234 | 链表 |
| 第 5–6 周 | 704, 35, 278, 33 | 二分 |
| 第 7–8 周 | 104, 226, 101, 94 | 二叉树 |
| 第 9–10 周 | 70, 198, 53, 322 | 动态规划入门 |

**同一个专题连着做**，套路见五次就长出手感。不要每天随机点一题。

## 七、断档了怎么办

- 断 1 天：不补，第二天接着做
- 断 3 天以上：降级成每周 5 题，周中做，周末留给项目
- 只剩 10 分钟：重做一道「独立做出 = 否」的旧题，也算完成

连续性比数量重要。断在完美主义上最不值。
